# LoA 장비·스탯·강화 시스템 구현 계획서

2026-10-21 작성

## 개요

목표는 "클리어 → 재료 → 재련 → 스펙 상승 → 더 빠른 클리어" 보상 루프를 닫는 것이고, 7단계로 나눠 순서대로 진행합니다. 지금 버전의 밸런스(AttackPower 7,911,200 · 보스 HP 4,746,719,168 · 실전 킬타임 약 4분)는 그대로 "기준 스펙(아이템 레벨 1640)"으로 고정합니다. 그래서 어느 단계에서 멈춰도 게임이 깨지지 않습니다.

현재 상태:

- 공격력은 `DA_Sorceress.AttackPower` 고정값이고, 스킬 8종이 각자 `AttackPower × 계수`를 계산합니다. 기본공격만 BP 발사체가 따로 계산합니다.
- 클리어하면 기록(`RecordClear`)만 남고 보상이 없습니다.
- 소지품(10x10)·실링·상점은 있지만 아이템 정의가 C++ 표(`ItemRegistry.cpp`)이고, 칸이 `ItemId`+`Count`만 들고 있습니다.

| 단계 | 내용 | 새로 생기는 것 | 앞 단계 의존 |
| --- | --- | --- | --- |
| 1 | 스탯 모델 + 데미지 계산 통합 | `UStatComponent`(지능·무기공격력·체력 + 전투 특성 6종), `ULoADamageLibrary` | 없음 |
| 2 | 허수아비 + 데미지 미터 | `ATrainingDummy`, `UDamageMeterWidget` | 1 |
| 3 | 장비 6부위 + 아이템 레벨 | 장비 인스턴스, 장비 창, 아이템 DataTable | 1 |
| 4 | 재련 + 장인의 기운 | 재련 NPC/창, 재련 DataTable | 3 |
| 5 | 클리어 보상 | 드랍 DataTable, 보상 표시 | 4 |
| 6 | 장신구 · 전투 특성 | 치명/특화/신속, 장신구 3부위 | 3 |
| 7 | 보석 · 각인 | 보석 11칸, 각인 버킷 | 6 |

이 문서는 계획만 담습니다. 코드와 에셋은 아직 하나도 바꾸지 않았습니다.

## 1단계 — 스탯 모델 + 데미지 계산 통합

캐릭터에 로아식 스탯(주 스탯·무기 공격력·체력 + 전투 특성 6종)을 만들고, 데미지를 두 곳에서만 계산하도록 바꿉니다. 시전 시점에는 스탯으로 피해를 계산하고, 피격 시점에는 치명·제압을 판정합니다. 장비(3단계)·장신구(6단계)는 나중에 이 스탯에 수정치를 더하기만 하면 됩니다.

### 조사 결과 — 지금 스탯과 계산이 흩어진 곳

스탯은 `UCharacterDataAsset`(`DA_Sorceress`)의 `MaxHP`·`MaxMP`·`MPRegenRate`·`MoveSpeed`·`AttackPower` 5개뿐이고, `AttackPower`는 고정값입니다. 캐릭터(`ALoACharacter::AttackPower`)가 이 값을 복사해 들고 있습니다.

| 경로 | 위치 | 계산 |
| --- | --- | --- |
| 스킬 7종 | `SkillDoomsday/Cheonbeol/Explosion/Inferno/IceArrow/FrostCall/Gust.cpp` | `Character->AttackPower × 계수` (캐릭터가 없으면 100) |
| 블레이즈 화상 | `SkillBlaze.cpp:56` | `AttackPower × BurnDamageRatio` |
| 기본공격 | `ABP_BasicAttack` (BP) | `AttackPower × GetSlotSkillData(8).DamageCoefficient` |
| 피격 적용 | 스킬 액터 6종의 `ApplyRadialDamage` → `AEchidnaBoss::TakeDamage` → `ReceiveDamage` | 들어온 값을 그대로 적용 |

### 스탯 구조

스탯은 세 층으로 나눕니다. 입력(기본 스탯·전투 특성 포인트)만 저장하고, 결과(`FCombatStats`)는 입력이 바뀔 때만 다시 계산해 캐시합니다.

**1. 기본 스탯** — 공격력과 최대 HP를 만듭니다.

| 스탯 | 용도 | 시작값 (`DA_Sorceress`) |
| --- | --- | --- |
| 지능 | 주 스탯. 소서리스는 마법사 계열이라 지능입니다(로아: 전사 힘 / 암살자·헌터 민첩 / 마법사 지능) | 200,000 |
| 무기 공격력 | 공격력 공식의 다른 한쪽 | 100,000 |
| 체력 | 최대 HP | 지금 최대 HP 100,000이 나오는 값 |

```
공격력 = K × sqrt(지능 × 무기공격력 / 6)
최대 HP = 기본 HP + 체력 × 계수
```

- 루트 안은 로아 실제 공식입니다. 한쪽만 올리면 효율이 떨어져서, 3단계부터 무기와 방어구를 같이 강화하게 됩니다.
- 주 스탯은 `EPrimaryStat`(힘/민첩/지능)으로 두고 `DA`에서 직업별로 고릅니다. 지금은 지능만 쓰지만, 나중에 직업이 늘어도 공식은 그대로입니다.
- `K`(`AttackPowerScale`)는 이 프로젝트의 스케일(보스 HP 47억)에 맞추는 상수입니다. UI에는 K를 곱하기 전 값을 보여줘서 로아 같은 숫자 감각을 유지합니다.
- 시작값의 루트 값은 57,735입니다. K는 아래 "기준값 맞추기"에서 정합니다.
- 체력은 졸업까지 최대 HP +15%까지만 오르게 합니다(밸런스 기준표의 "HP 함정").

**2. 전투 특성 6종** — 로아의 6종을 enum(`ELoACombatStat`)과 저장 필드로는 전부 만들고, 효과는 이 게임에 연결할 곳이 있는 것만 켭니다.

| 특성 | 1포인트당 효과 | 적용 위치 | 1단계 |
| --- | --- | --- | --- |
| 치명 | 치명타 적중률 +0.0358% (로아와 거의 동일) | 피격 시점 (`ResolveIncomingHit`) | 구현 |
| 특화 | 캐스팅·차지 스킬(종말·천벌·익스플로전) 피해 +0.05% | 시전 시점 (`CalcOutgoingDamage`, 스킬 타입 조회) | 구현 |
| 신속 | 쿨타임 감소 +0.0215%, 이동·공격·캐스팅 속도 +0.0172% | `StartCooldown`, `MaxWalkSpeed`, 캐스팅 시간, 기본공격 쿨타임 | 구현 |
| 제압 | 그로기 중인 보스에게 주는 피해 증가 | 피격 시점 (`AEchidnaBoss::IsGroggy()`) | 구현 (수치는 2단계에서 정함) |
| 인내 | 방어력·보호막·회복 | — | 필드만. 짤패턴 데미지가 절대값이라 방어력을 넣으면 "5~8대면 사망" 설계가 무너짐 |
| 숙련 | 상태이상 지속·무력화 피해 | — | 필드만. 보스에게 거는 상태이상이 없고, 무력화가 피해로 깎는 게이지가 아니라 시간 바라서 걸 곳이 없음 |

- 특화 계수 0.05%의 근거: 계수 재분배(2026-10-22) 후 캐스팅 3종이 딜의 약 65%라서, 전체 딜로 환산하면 1포인트당 약 +0.033%입니다. 치명 1포인트(기대값 약 +0.036%)와 거의 같아서 어느 쪽도 정답이 아닙니다. (재분배 전엔 49%라 0.07%였음)
- 제압의 의미: 카운터 성공(5초)·거울 카운터 마무리(3초) 그로기가 딜타임이 됩니다. 그로기 시간 비중이 작으므로 1포인트 효과는 치명·특화보다 커야 합니다. 정확한 값은 2단계 미터로 그로기 딜 비중을 잰 뒤 정합니다.
- 신속 규칙
    - 쿨감은 30%에서 상한(cap)을 둡니다(7단계 쿨감 보석과 공유).
    - 대시·즉시 기상(슬롯 18·19)은 쿨감 대상에서 뺍니다. 딜 스탯이 생존기를 줄이면 패턴 난이도가 무너집니다.
    - 거울 카운터의 카운터 쿨타임 오버라이드(5초)는 쿨감을 받지 않습니다.
    - 이동속도가 오르면 "걸어서 피할 수 있는" 패턴(추적 장판 8도/초 등)이 쉬워집니다. 시작값이 0이라 1단계에서는 영향이 없지만, 6단계에서 장신구 수치를 정할 때 확인합니다.
- 인내·숙련은 효과 0이지만 필드가 있어서, 나중에 보호막·무력화 게이지가 생기면 저장 구조를 바꾸지 않고 켤 수 있습니다.

**3. 결과 `FCombatStats`** — 공격력, 최대 HP, 치명률, 치명피해, 특화 배율, 쿨감, 이동·공격·캐스팅 속도, 제압 배율, 피해증가 버킷들(합연산·곱연산, 7단계 각인용).

### 시작 스펙과 기준값 맞추기

- 시작 전투 특성은 **치명 280**(= 치명률 10.02%)만 둡니다. 특화·신속·제압은 0입니다. 효과는 1단계에서 연결하되, 수치는 6단계 장신구가 가져옵니다(그때 이 DA 값을 시작 장신구로 옮김).
- 기본 치명률 0%, 치명피해 200%입니다. 치명 기대값이 1.1002배가 되므로, 공격력을 7,911,200 ÷ 1.1002 ≈ **7,190,500**으로 낮춰 지금 DPS를 유지합니다.
- 그러면 K = 7,190,500 ÷ 57,735 ≈ **124.5**입니다.
- **백/헤드어택 보너스는 없습니다.** 로아에서도 [백어택]/[헤드어택] 태그가 붙은 스킬만 받는데, 소서리스는 **타대 클래스**라 그런 스킬이 없습니다. 방향 클래스를 추가할 때 `FSkillData`에 방향 태그를 두고 `ResolveIncomingHit`에서 판정합니다(정면 판정 `IsHeadAttackPosition()`은 카운터용으로 이미 있음).

### 데미지 계산

1. **`ULoADamageLibrary::CalcOutgoingDamage(Instigator, Coefficient, SkillRowName)`** — 시전 시점
    - 공격력 × 계수 × 특화(해당 스킬만) × (1 + Σ합연산) × Π곱연산.
    - 스킬별 보석(7단계)을 위해 스킬 행 이름을 함께 받습니다.
    - 스킬 8종의 `AttackPower × 계수`를 이 함수 호출로 교체합니다. `BlueprintCallable`로 열어 `ABP_BasicAttack`도 이걸 부르게 합니다.
2. **`ULoADamageLibrary::ResolveIncomingHit(...)`** — 피격 시점, `AEchidnaBoss::TakeDamage`에서 1회
    - `EventInstigator`의 폰 → `UStatComponent`를 찾아 치명 판정 + 제압(보스가 그로기 중일 때)을 곱합니다.
    - 공용 함수로 두는 이유: 2단계 허수아비도 같은 함수를 불러야 보스와 계산이 같아집니다.
    - 피격 시점에 두는 이유: `ApplyRadialDamage`는 범위 안 모든 대상에 같은 값을 넘기므로, 치명을 시전 시점에 굴리면 타수별로 따로 터지지 않습니다.
    - 기존 규칙 유지: `Super`의 반환값이 아니라 인자 `DamageAmount`를 씁니다(데미지 0 버그 대응).
    - 치명 여부는 `ADamageNumberActor`로 넘겨 치명타 숫자를 노랑·크게 표시합니다.
3. **`FLoADamageEvent`** — 피격 결과(최종값, 치명, 그로기 여부, 스킬 행 이름)를 담아 `OnDamageDealt` 델리게이트로 보냅니다. 2단계 데미지 미터가 이걸 구독합니다.
    - 어느 스킬인지는 스킬 액터가 `SkillRowName`을 들고 `DamageCauser`로 넘어오는 것을 이용합니다(`ILoADamageSource` 인터페이스). 스킬별 `UDamageType` 서브클래스는 만들지 않습니다.

최종 공식은 이렇습니다.

```
피해 = 공격력 × 계수 × 특화 × (1 + Σ합연산) × Π곱연산 × 치명 × 제압
```

실제 피격에서는 치명을 확률로 굴립니다. 밸런스 계산에서는 치명 항을 기대값 `1 + 치명률 × (치명피해 − 1)`로 씁니다.

### `UStatComponent` (캐릭터에 부착)

- 입력: 기본 스탯(`DA_Sorceress`) + 전투 특성 포인트 + 수정치 목록(3단계부터 장비·장신구·보석·각인이 등록).
- `RecalculateStats()` → `FCombatStats` 캐시 → `OnStatsChanged` 브로드캐스트. 매 틱 계산하지 않습니다.
- `OnStatsChanged`를 받아 `MaxWalkSpeed`(`DA.MoveSpeed` × 이동속도), 최대 HP(현재 HP 비율 유지)를 갱신합니다.
- 기존 `ALoACharacter::AttackPower` 필드는 지우지 않고, 재계산 때 컴포넌트가 값을 써넣습니다. BP 참조가 깨지지 않게 하려는 것입니다. 새 코드는 컴포넌트의 값을 읽습니다.
- `DA_Sorceress.AttackPower`는 더 이상 읽지 않습니다. 남겨두되 "미사용" 주석을 답니다. C++ 기본값이 에셋에 덮어쓰이는 함정 때문에, 새 필드의 실제 값은 반드시 `DA_Sorceress` 에셋에 넣고 PIE 로그로 확인합니다.

### 작업 순서

1. `EPrimaryStat` / `ELoACombatStat` / `FCombatStats` + `UStatComponent`. `UCharacterDataAsset`에 주 스탯 종류·지능·무기공격력·체력·K·시작 특성 필드 추가, `DA_Sorceress`에 값 입력. 새 컴포넌트·UPROPERTY 추가라 **에디터를 닫고 풀 빌드**합니다.
2. `CalcOutgoingDamage` → 스킬 8종 교체 → `ABP_BasicAttack` 교체. 이 시점에는 치명·특화 없이 숫자가 지금과 같아야 합니다(공격력 7,911,200이 나오게 K를 임시로 맞춤).
3. `ResolveIncomingHit` + `OnDamageDealt` + 치명타 숫자. 치명 280을 켜는 커밋에서 K를 124.5로 **같이** 바꿉니다. 따로 하면 중간 상태의 DPS가 틀어집니다.
4. 특화·제압 연결.
5. 신속 연결(`StartCooldown`, 이동속도, 캐스팅 시간, 기본공격 쿨타임).

2번과 3번을 나누는 이유: 한 번에 하면 숫자가 달라졌을 때 리팩터링 실수인지 치명 때문인지 구분할 수 없습니다.

### 테스트 도구

- 콘솔 `LoAStats`: 현재 기본 스탯·전투 특성·`FCombatStats`를 로그로 찍습니다.
- 콘솔 `LoASetStat Crit 500` / `LoASetStat Swiftness 800` 같은 임시 오버라이드로, 장비 없이도 공식을 검증합니다. 쓴 판은 최고 기록에 남기지 않습니다(기존 치트 규칙).
- `[Damage]` 로그에 스킬 이름 / 기본값 / 치명 / 그로기 / 최종값을 남깁니다.

### 검증

- 작업 순서 2 직후: 각 스킬을 한 번씩 맞혀, 데미지 숫자가 기존 표(데미지/HP 밸런스 섹션)와 같은지 확인합니다.
- 작업 순서 3 직후: `LoASetStat Crit 0`이면 스킬별 데미지가 기존 표 × (7,190,500 ÷ 7,911,200)인지 확인합니다.
- 신속: `LoASetStat Swiftness 1000`이면 쿨타임 -21.5%(돌풍 14초 → 약 11초), 대시·기상은 그대로, 쿨감은 30%를 넘지 않는지 확인합니다.

선행 조건은 없고, 이후 모든 단계가 이 구조 위에 올라갑니다.

## 2단계 — 허수아비 + 데미지 미터

로비에 허수아비를 세우고, 스킬별 딜 비중과 DPS를 보여주는 미터를 만듭니다. 이후 모든 스탯 수치는 이 화면에서 "목표 DPS가 나오는가"로 검증합니다.

### `ATrainingDummy` (`Lobby/TrainingDummyActor`)

- 캐릭터 에셋이 없으므로 상점 NPC처럼 엔진 마네킹을 쓰고, 없으면 Cylinder로 대체합니다.
- HP 무한(맞아도 안 죽음), 보스와 같은 `UBossDirectionIndicatorComponent`를 붙여 카운터(정면) 연습도 할 수 있게 합니다.
- 피격 보정은 1단계에서 보스에 넣은 로직을 공용 함수(`ULoADamageLibrary::ResolveIncomingHit`)로 빼서 둘 다 부릅니다. 보스와 허수아비의 계산이 달라지면 검증이 무의미해지기 때문입니다.
- 보스 방어력을 나중에 넣는다면 허수아비도 같은 값을 갖게 합니다.
- 배치: 정비소와 입장 구역 사이의 아래쪽(-Y). 상점 NPC(+Y 벽)와 반대쪽입니다.
- 데미지 숫자는 기존 `ADamageNumberActor`를 그대로 씁니다.

### `UDamageMeterComponent` (플레이어 컨트롤러)

- `OnDamageDealt`를 구독해 세션별로 집계합니다. 대상은 보스와 허수아비 둘 다입니다.
- 세션 시작 = 첫 피격, 종료 = 마지막 피격 후 5초 무피격(허수아비) 또는 보스 처치/실패.
- 스킬별 집계값: 총피해, 타수, 치명 타수, 백·헤드 타수, 최대 한 방, 사용 횟수.

### `UDamageMeterWidget` (C++ 트리, WBP 없음)

- 화면 오른쪽 중단에 둡니다. 보스 맵에서는 미니맵 아래입니다.
- 상단: 전투 시간, 총피해, DPS, 치명률, 백·헤드 비율
- 본문: 스킬별 한 줄 — 아이콘, 딜 비중 막대, 비중 %, DPS. 비중 순으로 정렬합니다.

- 클리어 화면(`UClearWidget`)의 결과 줄에 "DPS"와 "최대 비중 스킬"을 추가합니다.

### 검증

- 기본공격 딜 비중이 6~7%인지 확인합니다(기존 설계 의도).

## 3단계 — 장비 6부위 + 아이템 레벨

무기·투구·상의·하의·장갑·어깨 6부위를 넣고, 아이템 레벨(6부위 평균)이 공격력과 최대 HP를 정하게 합니다. 재련은 아직 없고, 단계마다 스탯이 고정된 장비로 먼저 구조를 검증합니다.

### 데이터 — 정의와 인스턴스를 분리

지금 소지품은 `FInventorySlot`(ItemId·Count·bLocked) + 플라이웨이트 정의입니다. 회복약은 여기서 끝나지만, 장비는 같은 정의라도 재련 단계·품질이 제각각이라 인스턴스 데이터가 필요합니다.

| 구조체 | 내용 | 저장 위치 |
| --- | --- | --- |
| `FItemDefinition` (기존) | 이름·아이콘·카테고리·판매가. `EItemCategory::Equipment`는 이미 있음 | `ItemRegistry.cpp` → **`DT_Items`로 이전** |
| `FEquipmentDefinition` (신규) | 부위(`EEquipSlot`), 기본 아이템 레벨, 부위별 기본 스탯(무기=무기공격력, 방어구=지능·체력) | `DT_Equipment` |
| `FEquipmentInstance` (신규) | `FGuid InstanceId`, `DefinitionId`, `RefineLevel`, `Quality`(0~100), `ArtisanEnergy`(4단계), `bLocked` | 소지품 컴포넌트의 `TMap<FGuid, FEquipmentInstance>` |
| `FInventorySlot` (변경) | `FGuid EquipmentId` 필드 추가. 장비 칸은 `Count=1`이고 이 GUID로 인스턴스를 찾음 | 기존 100칸 배열 그대로 |

- 칸 배열은 그대로 둡니다. 그래서 정렬·잠금·드래그·변경 칸 다시 그리기(`OnSlotChanged`)는 거의 손대지 않습니다.
- 변경이 필요한 곳은 세 군데입니다.
    - **합치기**: `MaxStack`이 1이면 합치지 않습니다.
    - **정렬**: 장비는 종류별 합산을 건너뛰고 아이템 레벨 내림차순입니다.
    - **판매 목록**: `SellReserve`가 GUID를 들고 있도록 바꿉니다.

### 컴포넌트

- **`UEquipmentComponent`** (캐릭터): 부위별 장착 GUID 6개(6단계에서 장신구 5개 추가).
    - `Equip(InventoryIndex)` / `Unequip(Slot)`: 소지품 칸과 장착 칸의 GUID를 맞바꿉니다. 인스턴스는 소지품 컴포넌트의 맵에 그대로 둡니다.
    - 바뀔 때마다 `UStatComponent::RecalculateStats()`.
    - `GetItemLevel()` = 6부위 아이템 레벨 평균. 부위 레벨 = 기본 레벨 + 재련 단계 × 5입니다.
- **장착 제한**: 스킬 등록과 같은 규칙으로 보스 맵에서는 장착 변경을 막습니다. 로비에서는 어디서나 가능합니다.

### 장비 → 스탯

- 공식(`공격력 = K × sqrt(지능 × 무기공격력 / 6)`)과 K는 1단계에서 이미 정했습니다. 장비는 `UStatComponent`에 수정치를 등록하기만 합니다(무기 = 무기공격력, 방어구 = 지능·체력).
- 1단계에서 `DA_Sorceress`에 넣었던 시작 지능·무기공격력·체력을 1640 시작 세트로 옮깁니다. 맨몸 기본값은 0에 가깝게 낮추고, 시작 세트를 입었을 때 1단계와 같은 값이 나오게 맞춥니다.

### UI — 장비 창 (P키, C++ 트리)

- 왼쪽에는 부위 칸 6개(+장신구 자리를 비워둠)를 두고, 칸마다 아이콘, `+재련단계`, 품질 막대를 표시합니다.
- 오른쪽에는 아이템 레벨(크게), 공격력, 최대 HP, 전투 특성(6단계부터)을 둡니다.
- 소지품 장비 우클릭 = 장착, 장비 창 칸 우클릭 = 해제, 드래그도 지원합니다. 상점이 열려 있을 때는 우클릭이 기존처럼 판매로 작동합니다.
- 마우스를 올리면 툴팁을 띄웁니다. 툴팁에는 현재 착용 장비 대비 스탯 차이(▲▼)가 들어갑니다. 툴팁 위젯은 소지품에도 아직 없으므로 공용으로 만듭니다.
- 아이콘은 에셋이 없으므로 실링 아이콘처럼 PIL로 임시 아이콘 6장(부위 실루엣)을 만듭니다.

### 입장 제한 · 저장

- `ARaidEntranceActor`에 `RequiredItemLevel`(1620)을 두고, 미달이면 카운트다운 대신 "입장 가능 아이템 레벨 1620" 알림을 띄웁니다.
- `ULoAGameInstance` + `ULoASaveGame`에 장비 인스턴스 맵과 장착 GUID를 추가합니다. `SaveVersion` 필드를 넣어 이후 호환성을 챙깁니다.
- 첫 지급: 1640 세트 한 벌(지금 밸런스와 동일). 실링처럼 별도 플래그(`bHasStarterGear`)로, 기존 저장 파일에도 한 번 지급합니다.

### 검증

- 시작 세트 착용 상태의 허수아비 DPS가 2단계 측정값과 같아야 합니다.
- 한 부위를 벗으면 아이템 레벨·공격력·DPS가 기대대로 떨어지는지 확인합니다.
- 저장 → 재시작 → 레벨 이동을 거쳐도 장착이 유지되는지 확인합니다.

## 4단계 — 재련 + 장인의 기운

장비를 +10(1640)에서 +25(1715)까지 올리는 확률형 강화를 넣습니다. 천장(장인의 기운) 덕분에 한 부위를 +25까지 올리는 데 평균 약 105회, 6부위 합계 약 630회가 듭니다.

### 규칙

- 한 단계 성공 = 부위 아이템 레벨 +5, 부위 스탯 +2.0%. +10 → +25 전체가 ×1.35가 되도록 밸런스 기준표의 배율 예산에서 역산했습니다.
- 실패해도 단계가 떨어지거나 장비가 파괴되지 않고, 재료만 소모합니다(로아와 동일).
- 실패 보정: 실패할 때마다 현재 확률에 기본 확률의 10%를 더합니다. 상한은 기본의 2배입니다.
- **장인의 기운**: 실패할 때마다 "그번 성공 확률 × 46.51%"가 쌓입니다. 100%가 되면 다음 시도는 확정 성공이고, 성공하면 0으로 돌아갑니다. 기운은 장비 인스턴스(`ArtisanEnergy`)에 저장합니다.
- 확률은 클라이언트 `FMath::FRand()`로 굴립니다. 싱글 게임이라 서버 검증은 필요 없습니다. 다만 시도하자마자 저장해서 재시작으로 되돌리는 꼼수(세이브 스컴)를 막습니다.

### 확률표와 기대 시도 횟수 (`DT_Refine`)

기대 시도와 천장은 위 규칙 그대로 계산한 값입니다. 재료량은 초안이고, 5단계 경제 설계에서 맞춥니다.

| 목표 단계 | 아이템 레벨 | 기본 확률 | 기대 시도 | 천장 (최악) | 파괴석/수호석 (1회) | 돌파석 (1회) | 실링 (1회) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| +11~+12 | 1645~1650 | 45% | 2.0 | 6회째 | 10 | 1 | 20,000 |
| +13~+15 | 1655~1665 | 30% | 2.8 | 7회째 | 12 | 2 | 30,000 |
| +16~+18 | 1670~1680 | 15% | 4.9 | 11회째 | 15 | 3 | 45,000 |
| +19~+21 | 1685~1695 | 10% | 6.6 | 15회째 | 18 | 4 | 60,000 |
| +22~+23 | 1700~1705 | 5% | 11.4 | 26회째 | 22 | 6 | 80,000 |
| +24~+25 | 1710~1715 | 3% | 17.5 | 40회째 | 25 | 8 | 100,000 |

- 무기는 파괴석, 방어구는 수호석을 씁니다. 무기는 재료를 1.5배 씁니다. 로아처럼 무기를 먼저 올리게 하려면, 무기의 단계당 상승폭을 키우고 방어구를 줄여 총합(×1.35)을 맞춥니다.
- 선택 재료 **숨결**(로아의 빙하/용암의 숨결): 넣으면 성공 확률이 기본 확률만큼 더 올라갑니다. 상점에서 실링으로만 팔아 실링 소모처 역할을 합니다.

### UI — 재련 NPC

- 상점 NPC(`AShopNPCActor`)와 같은 방식으로 로비에 재련 NPC(`ARefineNPCActor`)를 둡니다. G키 / 우클릭으로 열고, 카메라 연출과 붙잡힘도 그대로 재사용합니다. 공통 부분은 `AInteractableNPCActor` 부모 클래스로 뽑습니다.
- 재련 창 구성
    - 왼쪽: 착용 중인 부위 6개 목록(현재 단계·장인의 기운 %)
    - 가운데: 선택한 장비 `+N → +N+1`, 성공 확률, 장인의 기운 막대, 소모 재료(보유/필요, 부족하면 빨간색), 숨결 체크박스
    - 하단: [재련] 버튼
- 연출: 재련을 누르면 약 1.2초 동안 막대가 차오른 뒤 성공(금빛 + "재련 성공")이나 실패(회색 + 장인의 기운 상승분 표시)를 보여줍니다. 연출 중에는 버튼을 비활성화합니다.
- 대사창은 상점의 하단 대화창 위젯을 재사용합니다.

### 코드

- `URefineLibrary::TryRefine(Equipment, Inventory, Instance, bUseBreath)` → 결과 enum(성공/실패/재료 부족/최대 단계). 재료 차감, 확률 굴리기, 기운 갱신, `RecalculateStats`, 저장을 한 함수에서 처리합니다.
- 실패 보정 누적치도 `FEquipmentInstance`에 둡니다(`FailBonusSteps`).
- 테스트 콘솔: `LoAGiveItem DestructionStone 1000`(기존 명령), `LoASetRefine Weapon 20`.

### 검증

- 콘솔 `LoARefineSim 25 10000`: 한 단계를 1만 번 시뮬레이션해 평균 시도가 위 표와 맞는지 확인합니다. 예를 들어 3%면 약 17.5회가 나와야 합니다.
- 천장 회차에서 반드시 성공하는지도 확인합니다.

1. `AEchidnaBoss::HandleDefeated` → `ULoAGameInstance::RollRaidReward()`가 보상 목록을 만들어 `PendingRewards`에 저장합니다.
2. `UClearWidget` 결과 줄에 아이콘 + 개수를 표시합니다. 원래 레퍼런스의 "전리품 줄" 자리를 클리어 시간이 대신하고 있던 곳입니다. [더보기] 버튼도 여기 둡니다.
3. 즉시 소지품에 `AddItem`합니다. 칸이 모자라 못 넣은 분량은 `PendingRewards`에 남기고, 로비에서 칸이 생기면 지급하며 알림을 띄웁니다. 그래서 보상이 사라지지 않습니다.
4. 저장: 보상을 굴린 직후 SaveGame에 씁니다. 클리어 화면에서 게임을 꺼도 보상이 남습니다.

### 새 아이템 정의 (`DT_Items`)

| ItemId | 카테고리 | MaxStack | 판매가 |
| --- | --- | --- | --- |
| `GuardianStone` (수호석) | Material | 9,999 | 10 |
| `DestructionStone` (파괴석) | Material | 9,999 | 20 |
| `LeapStone` (돌파석) | Material | 999 | 50 |
| `RefineBreath` (숨결) | Material | 999 | 0 (상점 구매 전용) |

아이콘은 PIL 임시 아이콘을 쓰고, `/Game/LostArk/UI/Item/`에 둡니다(이미 항상 쿡되는 폴더).

## 6단계 — 장신구 · 전투 특성

장신구 5칸에서 치명·특화·신속을 얻습니다. 강화하는 장비가 아니라 "좋은 옵션을 뜯는" 파밍용 장비입니다. 성장 폭은 시작 장신구 대비 최상급 약 +10%로 제한합니다.

### 장신구

| 부위 | 칸 | 전투 특성 | 수치 범위 (시작 → 최상급) |
| --- | --- | --- | --- |
| 목걸이 | 1 | 2종 | 각 350 → 420 |
| 귀걸이 | 2 | 1종 | 200 → 240 |
| 반지 | 2 | 1종 | 200 → 240 |

- 합계는 시작 약 1,500 → 최상급 약 1,800입니다.
- 드랍 시 특성 종류(치/특/신)와 수치를 굴립니다. 굴린 값은 3단계의 `FEquipmentInstance`에 `TArray<FStatRoll>`로 둡니다. 장신구는 재련하지 않습니다(로아와 동일).
- 로아처럼 "치특"·"특신" 같은 조합 선택이 빌드가 됩니다. 목걸이의 2종 조합이 가장 귀한 옵션입니다.
- 판매가를 두어 필요 없는 장신구는 상점에 팔 수 있게 합니다. 판매 탭은 이미 있습니다.

### 전투 특성

- 6종의 정의와 1포인트당 효과는 1단계에서 이미 구현했습니다(1단계 "전투 특성 6종" 표). 이 단계는 그 포인트의 **출처**를 장신구로 만드는 것입니다.
- 장신구가 굴리는 특성은 치명·특화·신속·제압 4종입니다. 인내·숙련은 효과가 없으므로 드랍 후보에서 뺍니다.
- 특화 캐스팅 빌드는 딜이 크고 캐스팅이 끊기면 손해입니다. 이 게임의 패턴 회피와 맞물려 손타를 보상하는 선택지가 됩니다.
- 신속은 스킬 점유율(현재 0.35)을 올리고 이동속도도 올립니다. 이동속도가 오르면 걸어서 피하는 패턴이 쉬워지므로, 최상급 장신구 기준 이동속도가 몇 %인지 여기서 확인합니다.

### 도입 시 기준 재조정

- 1단계에서 `DA_Sorceress`에 넣은 시작 특성(치명 280)을 시작 장신구로 옮깁니다. 시작 장신구 총합은 약 1,500이므로, 특화·신속이 새로 생긴 만큼 `K`를 다시 역산해 기준 DPS를 그대로 유지합니다. "1640 시작 세트의 허수아비 DPS"가 언제나 불변식입니다.
- 장비 창 오른쪽에 치명률, 특화 효과, 쿨감을 실제 % 값으로 표시합니다.

## 7단계 — 보석 · 각인

보석은 "스킬별 강화", 각인은 "플레이 방식 선택"입니다. 성장 폭은 보석 약 +12%, 각인 약 +8%로 제한하고, 나머지 가치는 빌드 다양성에서 나오게 합니다.

### 보석

- 11칸(로아와 동일). 보석 하나는 스킬 하나를 지정합니다. 스킬 8개 × 2종 = 16가지 중 11개만 끼므로 무엇을 빼느냐가 선택이 됩니다.
- 종류 (로아의 겁화/작열)
    - 피해 보석: 그 스킬 피해 +2% × 레벨 (Lv10 = +20%). 스킬별 곱연산입니다.
    - 쿨감 보석: 그 스킬 쿨타임 -1% × 레벨 (Lv10 = -10%). 신속과 합연산하고 30% 상한을 함께 씁니다.
- 합성: 같은 종류·레벨 3개 + 실링 → 다음 레벨 1개. Lv10은 Lv1 3⁹ = 19,683개 분량이라 후반 실링 소모처 역할을 합니다.
- 획득: 클리어 보상(Lv1~3, 확률), 상점 구매(Lv1). 보석은 `MaxStack` 999인 일반 아이템으로 두고(예: `Gem_Dmg_05`), 스킬 지정은 보석 칸에 끼울 때 고릅니다. 그러면 인스턴스 데이터가 필요 없고 소지품 정렬·합치기가 그대로 동작합니다.
- 시작 스펙: Lv5 보석 11개를 지급하고 기준 DPS에 포함합니다(6단계와 같은 불변식). Lv5 → Lv10 전부 올리면 피해 약 +9%, 쿨감까지 합치면 약 +12%입니다.
- UI: 장비 창에 "보석" 탭을 두고, 스킬트리 창(K)의 스킬 행에도 장착된 보석 아이콘을 표시합니다.

### 각인 — 파워보다 선택

슬롯 3개를 두고 각인마다 Lv1~3을 둡니다. 책(각인서)을 읽어 레벨을 올립니다. 대부분 이 게임에 이미 있는 메커니즘과 연결되는 것들로 골랐습니다.

| 각인 | Lv3 효과 (로아 참고) | 연결되는 기존 시스템 |
| --- | --- | --- |
| 원한 | 보스 피해 +10%, 받는 피해 +10% | 데미지 밸런스 (짤패턴 5~8대 → 4~7대) |
| 타격의 대가 | 백/헤드어택이 아닌 스킬 피해 +16% | 소서리스가 타대 클래스라 전 스킬에 적용 (기습·결투의 대가는 방향 스킬이 없어 제외) |
| 예리한 둔기 | 치명피해 +40%, 일정 확률로 피해 -20% | 치명 빌드 |
| 아드레날린 | 스킬 사용마다 공격력 +1% (최대 6중첩), 중첩 최대 시 치명률 +12% | 스킬 점유율, 신속 |
| 각성 / 만개 | 대시·기상 쿨타임 -30% | 생존 빌드 (딜 0) |

- 각인 피해는 각각 별도 곱연산 버킷입니다(1단계 공식의 ∏).
- 시작 스펙에는 "원한 Lv1 + 아무거나 Lv1 2개" 수준을 포함합니다. Lv3 세 개를 다 맞추면 약 +8%가 되도록 레벨별 수치를 맞춥니다.
- 허수아비 미터에 각인별 기여도(백·헤드 비율, 최대 중첩 유지 시간)를 보여줘야 선택의 의미가 보입니다.
- 각인 변경은 로비에서만 허용합니다(스킬 등록과 같은 규칙).

## 밸런스 기준표

기준은 "1640 시작 스펙 = 지금의 실전 킬타임 4분"이고, 모든 성장을 끝내면 약 ×1.8(킬타임 약 2분 15초)입니다. 두 숫자를 먼저 정하고, 그 사이의 배율을 시스템별로 나눠 주는 방식입니다.

### 배율 예산 (시작 → 졸업)

| 시스템 | 배율 | 근거 |
| --- | --- | --- |
| 재련 +10 → +25 | ×1.35 | 단계당 +2.0% × 15단계 |
| 장신구 | ×1.10 | 특성 합계 1,500 → 1,800, 포인트당 약 +0.034% |
| 보석 Lv5 → Lv10 | ×1.12 | 피해 +9% + 쿨감 약 +3% |
| 각인 Lv1 → Lv3 | ×1.08 | 세 개 합산 |
| **합계** | **×1.80** | 1.35 × 1.10 × 1.12 × 1.08 |

예산을 먼저 정해두면, 나중에 시스템을 하나 더 넣어도 다른 시스템의 몫을 줄여 합계를 지킬 수 있습니다.

### 스펙별 목표

실전 킬타임 = 4분 ÷ 배율입니다. 패턴 등장 여부는 지금 트리거(정산 게이지 자연 상승, 광폭화 잔여 시간)로 계산했습니다.

| 스펙 | 아이템 레벨 | 배율 | 실전 킬타임 | 보는 큰 패턴 |
| --- | --- | --- | --- | --- |
| 입장 컷 (+6) | 1620 | ×0.92 | 약 4분 20초 | 똥장판·거울잇기·랜잡·거울 카운터 전부 |
| 시작 세트 (+10) | 1640 | ×1.00 | 4분 | 위와 같음 (그네는 5분 20초라 못 봄) |
| 중반 (+18) | 1680 | ×1.17 | 약 3분 25초 | 정산 100%까지는 여유 있음 |
| 재련 졸업 (+25) | 1715 | ×1.35 | 약 2분 58초 | 정산 100%는 아슬아슬 |
| 전부 졸업 | 1715 | ×1.80 | 약 2분 15초 | 정산 75%까지만 |

- 입장 컷(1620)은 시작 세트보다 낮아서 지금 구조에서는 의미가 없습니다. 하드 난이도(예: 입장 1680, 보스 HP ×1.4)를 넣을 때부터 제 역할을 합니다.
- **스펙이 오를수록 큰 패턴을 보지 못합니다.** 시간 패턴(그네 5분 20초, 랜잡 1분 20초)과 정산 게이지는 경과 시간 기준이라 빨리 잡을수록 사라집니다. 로아에서는 자연스러운 현상이지만, 보스가 하나뿐인 이 게임에서는 콘텐츠가 줄어드는 것이므로 결정이 필요합니다. 선택지는 세 가지입니다.
    - 그대로 둠(스펙 보상)
    - 시간 패턴을 HP 줄 트리거로 바꿈(거울 카운터처럼)
    - 하드 난이도로 고스펙을 끌어올림

### HP 함정 — 생존은 거의 안 오르게

- 짤패턴 데미지는 플레이어 HP 100,000 기준 절대값입니다(예: 4거울 1틱 4,000). "짤패턴 5~8대면 사망"이라는 설계를 지키려면 최대 HP가 거의 오르면 안 됩니다.
- 규칙: 체력 스탯은 졸업까지 최대 HP +15%까지만 올립니다(100,000 → 115,000). 그러면 짤패턴 허용 횟수가 최대 1대 늘어납니다.
- `MaxHP × 비율` 패턴(랜잡 90%, 그네·거울잇기 실패 ×10)은 영향을 받지 않으므로 그대로 둡니다.
- 원한 각인의 "받는 피해 +10%"는 `ALoACharacter::ReceiveDamage`의 광폭화 배율 옆에서 곱합니다.

## 리스크와 주의사항

가장 큰 위험은 시작 실링 1억과 세이브 호환성입니다. 나머지는 이 프로젝트가 이미 겪었던 함정을 다시 밟지 않는 것들입니다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 시작 실링 1억 | 졸업 실링 총량(약 4,880만)을 처음부터 넘어서 실링이 제한 역할을 못 함 | 5단계 도입 때 `StartingSilling`을 약 200만으로 낮춤. 기존 저장 파일은 `SaveVersion`을 보고 한 번 조정하거나 `LoA.sav`를 초기화 |
| 세이브 호환성 | 장비·재료·보석이 쌓인 뒤 구조를 바꾸면 데이터가 유실됨 | 3단계에서 `SaveVersion` + 로드 시 마이그레이션 함수 도입. 실링처럼 기능별 지급 플래그를 사용 |
| C++ 기본값이 에셋에 덮어쓰임 | 수치를 바꿔도 반영이 안 됨(`DA_Sorceress`, `BP_Echidna`, `ST_Echidna`) | 새 수치는 전부 DataTable에 두고 C++에는 폴백만 둠. 변경은 PIE 로그로 검증 |
| MCP CDO 쓰기가 PIE에서 null | 장비 창 같은 위젯 클래스를 컨트롤러에 할당해도 동작 안 함 | 새 UI는 미니맵·소지품처럼 WBP 없는 C++ 트리로 만들어 할당 자체가 필요 없게 함. 생성 지점마다 성공/실패 로그 |
| 구조체·UPROPERTY 타입 변경 | `FInventorySlot` 필드 추가, 새 컴포넌트는 Live Coding으로 불안정 | 1·3단계는 에디터를 닫고 풀 빌드 |
| 유니티 빌드 이름 충돌 | 새 cpp를 추가하면 익명 네임스페이스 헬퍼가 C2084 | 헬퍼에 파일 고유 접두어(예: `Refine_`, `Equip_`) |
| 쿡 누락 | 코드에서만 참조하는 아이콘·DataTable이 패키징 빌드에서 빠짐 | 아이콘은 `/Game/LostArk/UI/` 아래에, DataTable은 `/Game/LostArk/Data/`를 `DirectoriesToAlwaysCook`에 추가. 패키징 전 `ReferencedSet.txt` 대조 |
| 기본공격 BP 경로 | 1단계에서 `ABP_BasicAttack`만 빠지면 치명·장비 효과가 안 붙음(계수 누락 버그의 재현) | 허수아비 미터의 기본공격 비중(6~7%)으로 확인 |
| 카운터 쿨타임 오버라이드 | 신속·보석 쿨감이 거울 카운터의 5초 고정값과 겹침 | 오버라이드 중에는 쿨감을 적용하지 않음(`StartCooldown`에서 분기) |

### 단계별 완료 기준

- [ ] 1단계: 리팩터링 직후 스킬 8종의 데미지가 기존 표와 일치, `LoASetStat`으로 치명·특화·신속 효과가 공식대로 나옴
- [ ] 2단계: 허수아비 60초 DPS가 이론값의 80~95%
- [ ] 3단계: 시작 세트 착용 DPS = 2단계 측정값, 저장·레벨 이동 후 유지
- [ ] 4단계: `LoARefineSim` 평균이 확률표와 일치, 천장 확정 성공
- [ ] 5단계: 클리어 보상이 소지품에 들어오고, 칸이 가득 차도 유실되지 않음
- [ ] 6단계: 시작 장신구 포함 후에도 1640 기준 DPS 불변
- [ ] 7단계: 전부 졸업 상태의 허수아비 DPS가 기준 ×1.8 ±5%
