프로젝트 개요 및 범위

1.1 구현 목표

기존 LoA 솔로 플레이어 탑다운 ARPG 위에 보스 레이드 시스템을 신규 구축하고, 로스트아크 에키드나 2관문의 핵심 패턴을 재해석하여 싱글플레이어 경험으로 이식한다. 범용 몬스터 AI 시스템을 먼저 만드는 것이 아니라, 보스 전용 경량 아키텍처로 설계하여 최단 경로로 플레이 가능한 보스전을 완성하는 것을 목표로 한다.

1.2 구현 범위

✅ 포함

  • 보스 기본 클래스 (ABossBase)
  • 에키드나 보스 액터 (ABossEchidna)
  • 패턴 시스템 (UBossPatternBase + 파생)
  • 페이즈 1 / 페이즈 2 구분
  • 보스 HP 바 UI (MVVM)
  • 레이드 매니저 (시작/종료 조건)
  • AoE 패턴 액터 (장판, 발사체)
  • 카운터 게이지 시스템
  • 와이프 / 클리어 처리

❌ 제외 (추후)

  • 멀티플레이어 / 파티 시스템
  • 범용 몬스터 AI (NavMesh 기반)
  • 레이드 진입 게이트 UI
  • 드랍 / 보상 시스템
  • 전투 로그 / 딜 미터
  • 에키드나 전용 보이스
  • 2페이즈 이상 추가 패턴

1.3 기존 시스템과의 관계

기존 시스템레이드에서의 역할변경 필요 여부
LoACharacter (플레이어)TakeDamage 수신, HP 감소없음
SkillManagerComponent플레이어 스킬로 보스에 데미지없음
ApplyRadialDamageAoE 패턴 데미지 적용없음
HUD_ViewModel플레이어 HP/MP 바 (그대로 사용)없음
LoAPlayerController레이드 중 이동/스킬 입력 유지없음
TrainingDummy보스 데미지 수신 참고 구조참고만
💡 설계 원칙: 플레이어 측 코드는 건드리지 않는다. 보스 시스템은 완전히 독립된 디렉터리(Source/LoA/Boss/, Source/LoA/Raid/)에 구축하여 기존 기능에 영향을 주지 않는다.

3.6 패턴 선택 알고리즘

void ABossBase::ScheduleNextPattern() { // 가중치 기반 랜덤 선택 — 직전 패턴은 제외 (동일 패턴 연속 방지) TArray<FPatternEntry>& Pool = CurrentPhasePatterns; float TotalWeight = 0; for (auto& Entry : Pool) if (Entry.Pattern != LastPattern && Entry.Pattern->IsCooldownReady()) TotalWeight += Entry.Weight; float Roll = FMath::FRandRange(0, TotalWeight); float Accum = 0; for (auto& Entry : Pool) { if (Entry.Pattern == LastPattern) continue; Accum += Entry.Weight; if (Roll <= Accum) { ActivePattern = Entry.Pattern; break; } } // PostDelay(2~4s 랜덤) 후 Execute float Delay = FMath::FRandRange(MinPatternDelay, MaxPatternDelay); GetWorldTimerManager().SetTimer(PatternTimer, this, &ABossBase::ExecuteActivePattern, Delay, false); }

카운터 가능 패턴(PoisonBreath, Nexus) 실행 중 bCounterWindowOpen = true 플래그를 열고, 플레이어의 기본 공격 또는 특정 스킬이 보스에 명중 시 ABossBase::TryCounter()를 호출한다. 성공 시 패턴 Cancel() + 보스 다운 상태 3초 적용.

⚠️ 구현 주의: 카운터는 플레이어 스킬의 ApplyRadialDamage 결과가 보스에 닿을 때 확인한다. 별도의 카운터 전용 스킬 타입은 만들지 않고, 보스의 TakeDamage 내에서 bCounterWindowOpen 체크 후 처리한다.

7.2 기술 리스크

HIGH — 독뱀 소환체 NavMesh 충돌: 현재 프로젝트가 NavMesh 없이 RequestDirectMove로 이동하므로, 소환체도 NavMesh 없이 직접 AddMovementInput으로 추적해야 한다. 장애물 우회 불가 — 보스 아레나를 장애물 없는 평탄한 원형으로 설계하여 회피.
MID — 흡기(넥서스) 당기기 구현: AddActorWorldOffset으로 플레이어를 보스 방향으로 당기면 기존 이동 시스템(ControllerMoveVelocity)과 충돌 가능. 흡기 중 PlayerController 이동 입력을 일시 차단하거나, LaunchCharacter를 활용하는 방식 검토 필요.
MID — 보스 크기와 카메라 거리: 보스가 대형일 경우 기존 스프링암 거리(기본값)에서 화면에 잘 안 보일 수 있음. 레이드 진입 시 CameraBoom ArmLength를 일시적으로 증가시키는 처리 필요.
LOW — 패턴 동시 처리: 현재 설계는 한 번에 하나의 패턴만 실행(ActivePattern). 독뱀 소환 패턴이 완료 대기 중에 다른 패턴이 겹치지 않도록 IsComplete() 구현 주의 필요. 독뱀 타임아웃(30s) 안에 다음 패턴이 시작되지 않아야 함.
