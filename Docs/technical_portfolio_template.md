# 기술 포트폴리오 템플릿

> 목적: 프로젝트의 기능을 나열하는 대신, **왜 만들었는지 → 무엇을 고민했는지 → 어떻게 구현했는지 → 어떤 결과를 확인했는지**를 보여준다.  
> 사용법: 대괄호 `[ ]` 안의 안내 문구를 본인의 프로젝트에 맞게 채우고, 해당하지 않는 항목은 삭제한다.

---

## 작성 원칙

- **프로젝트 전체 목적부터 설명한다.** 전체 개요 없이 문제 해결 사례부터 시작하지 않는다.
- **담당 범위를 명확히 구분한다.** 팀이 만든 결과와 내가 직접 구현한 결과를 혼동하지 않는다.
- **기능보다 문제와 판단을 설명한다.** 기술을 사용한 이유와 대안을 고려한 이유를 적는다.
- **주장을 근거와 연결한다.** 코드, 구조도, 테스트, 측정값, 영상 등 확인 가능한 자료를 제시한다.
- **핵심 본문은 간결하게 유지한다.** 세부 코드·긴 설명·추가 영상은 링크로 분리한다.
- **기술 중심의 시각 자료를 사용한다.** 게임 화면은 맥락을 설명할 때 활용하고, 코드·구조·흐름·구현 결과를 중심으로 보여준다.
- **구현과 검증을 구분한다.** 기능을 구현했다는 사실만으로 성능 향상을 주장하지 않는다.
- **사실과 계획을 구분한다.** 측정하지 않은 수치나 확인하지 않은 결과를 작성하지 않는다.
- **한 페이지에는 핵심 메시지 하나를 둔다.** 불필요한 장식과 과도한 본문을 피한다.

## 권장 구성 요약

**핵심 본문:** 프로젝트 개요 → 전체 기능 및 기술적 개요 → 담당 역할 및 기여 범위 → 핵심 기술·문제 해결 사례 2~3개 → 성과 → 회고

**상세 자료:** 전체 코드, 긴 분석, 추가 테스트, 시연 영상, 성능 측정 자료

가장 중요한 기준은 **“무엇을 만들었다”에서 끝내지 않고, “왜 필요했고, 어떤 판단으로 구현했으며, 결과를 어떻게 확인했는가”까지 보여주는 것**이다.
